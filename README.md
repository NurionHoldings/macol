# 마컬 (MACOL)

> 통화하며 서로의 개인 템플릿을 보고 함께 작업하는 플랫폼

상태: 제품 구상 및 설계 기준 v0.1 · 2026-09-25. 구현·실증·운영 배포를 완료했다는 뜻이 아니다.

## 제품 약속

- 개인은 자기소개, 메뉴, 자료, 양식, 통화 선호도를 담은 개인 템플릿을 만든다.
- 두 사람이 음성으로 대화하면서 같은 세션의 템플릿을 본다.
- 한쪽이 메뉴를 선택하면 다른 쪽에도 해당 메뉴가 열린다. 양쪽은 각자의 권한에 따라 내용을 선택·작성·확인한다.
- 문서와 링크를 공유하고, 상대가 명시적으로 선택한 자료를 열람·다운로드할 수 있다.
- 통화 전 용건 제시, 통화 중 공동 작업, 통화 후 작업 이어가기를 하나의 흐름으로 제공한다.
- 화면 사용이 어려운 상황에는 음성통화만 지속할 수 있다.

## 통화 연결 경로와 현재 한계

1. **플랫폼 간 통화:** 양쪽이 마컬 앱/웹 통화 진입점을 사용할 때 통화 세션과 화면 세션을 함께 생성한다. 첫 구현·검증 대상으로 삼는다.
2. **일반 010 발신:** 일반 전화 앱으로 기존 010 번호에 걸었을 때 발신자 화면이 자동으로 열리는 기능은 현재 이 저장소에서 검증되지 않았다. 통신사/보이는 ARS 사업자 연동, 사용자 동의, 발신자 단말 지원, 기존 번호 연결 방식을 실제 회선에서 검증해야 한다.
3. **보조 경로:** 통신 연동이 없는 발신자에게는 별도 링크로 화면 세션에 참여하게 할 수 있다. 자동 팝업이나 발신번호 획득을 보장하지 않는다.

통신망 연결, 관공서 번호 예외 통과, 기존 010 직접 적용, 착신전환 없는 자동 실행을 구현 완료로 표시하지 않는다. 검증 전에는 데모 UI에서 실제 전화망 기능처럼 표현하지 않는다.

## 첫 번째 제품 흐름

1. 소유자가 템플릿을 생성·미리보기·공개한다. 이름, 소개, 메뉴, 자료, 양식, 공개 범위를 설정한다.
2. 상대가 템플릿을 열고 통화를 요청한다. 소유자는 수락·거절·용건 먼저 받기를 선택한다.
3. 통화 세션과 화면 세션을 연결한다. 양쪽 모두 참여 상태와 현재 공유 메뉴를 본다.
4. 메뉴 클릭이 상대방 화면에 전달된다. 각 화면은 메뉴 위치를 동기화하되, 파일 열기·다운로드·외부 이동은 각자 직접 선택한다.
5. 양식은 필드별 작성자/편집자 권한을 갖는다. 중요한 제출·확정·자료 공개에는 당사자의 명시적 동작이 필요하다.
6. 연결이 끊기면 재접속 상태를 표시하고, 허용된 임시 작업을 복원한다. 통화가 끝나면 세션을 닫고 허용된 결과만 남긴다.

## 공동 작업의 최소 규칙

- 서버가 세션 ID, 참가자 역할, 권한, 메뉴 버전과 이벤트 순번을 관리한다.
- 메뉴 이동 이벤트는 양쪽에 전달하되, 민감 메뉴·비공개 메뉴의 권한 검사를 먼저 수행한다.
- 입력 변경은 서버에서 권한과 버전을 검증한다. 동시 수정 충돌은 조용히 덮어쓰지 않고 사용자에게 보여준다.
- 참가자 이탈·재접속·중복 이벤트·순서 역전·만료 링크를 처리한다.
- 파일은 공개 범위와 만료 정책을 적용하고, 다운로드는 사용자 직접 실행만 허용한다.
- 통화 녹음, 음성 전사, AI 요약은 첫 범위에 넣지 않는다. 별도 동의와 정책 설계 후 추가한다.

## 아르카온 작업 경계

아르카온은 요구사항 정리 → 충돌 확인 → 아키텍처 → 시험 가능한 완료 기준 → 설계 잠금 → 작은 PR 순서로 작업한다. 기존 ARKAON 기능과 독립된 마컬 프로젝트 산출물을 사용하며, 모든 설계·변경의 근거와 실패 경로를 기록한다.

첫 산출물:
- 고객 여정·화면 흐름·통화 경로별 지원 범위
- 세션 상태도 및 권한 표
- 실시간 이벤트 계약과 재접속·충돌 처리
- 템플릿/자료/양식 데이터 모델과 공개 범위
- 플랫폼 간 동작 시연 및 검증 시나리오
- 010/보이는 ARS 통신 연동 실증 계획(사업자, 단말, 앱 설치/미설치, 실패 조건)

본격 개발은 설계의 완료 기준과 독립 감사 기준이 검토 가능해진 뒤 진행한다. 실제 외부 자원 생성, 전화 발신, 문자 발송, 유료 사용, 병합, 운영 배포는 각각 확인 가능한 실행 범위와 승인 기록에 따라 수행한다.

## 에테르니언 최종 검사 기준

- 서로 다른 두 기기에서 음성 통화 중 메뉴 선택이 양쪽에 반영되는가
- 권한이 없는 참가자가 비공개 메뉴·자료·입력에 접근할 수 없는가
- 동시 선택·수정, 연결 끊김, 재접속, 중복 이벤트에서 데이터가 일관되는가
- 다운로드와 제출이 사용자의 의도 없이 시작되지 않는가
- 통신 연동의 데모/시뮬레이션/실회선 결과가 구분되는가
- 자동 테스트, 수동 두 기기 시연, 접근성 점검과 변경 증거가 남아 있는가

검사 결과는 PASS / CONDITIONAL / FAIL로 판정하고, 실제 통신망 적용은 실회선 검증 없이는 PASS로 판정하지 않는다.

## 브라우저 공동 통화 시험 (Draft)

현재 `app.py`는 두 참가자에게 초대 링크를 발급하고, WebSocket으로 메뉴 이동·역할별 입력·WebRTC 연결 정보를 동기화합니다. 음성 미디어는 브라우저끼리 직접 전송됩니다. 010 전화망, ARS, 녹음, 파일 업로드와 운영 배포는 연결되지 않았습니다.

```bash
python -m pip install -r requirements.txt
export MACOL_OWNER_KEY='시험용으로 길고 무작위인 별도 키'
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

브라우저에서 `http://localhost:8000`을 열고 생성 키를 입력한 다음, 방문자 링크를 두 번째 브라우저에 전달합니다. 두 화면에서 메뉴 선택과 입력 동기화를 확인하고 각자 마이크 권한을 허용한 뒤 **음성 통화 시작**을 누릅니다. 원격 기기의 마이크 사용에는 HTTPS가 필요합니다. 로컬 개발 외 공개 서버는 TLS, 신뢰할 수 있는 호스트 설정, 단일 프로세스 상태 저장 또는 공유 저장소, 만료·로그 처리, 남용 제한을 먼저 갖춰야 합니다. 서로 다른 네트워크의 음성 연결에는 STUN/TURN 구성이 필요할 수 있습니다. `MACOL_STUN_URL` 환경 변수로 시험용 STUN 주소를 지정할 수 있지만, TURN 중계는 아직 제공하지 않습니다.

```bash
python -m pytest -q test_app.py
```

현재 서버 상태는 프로세스 메모리에만 보관되므로 재시작 시 방이 사라지고 단일 프로세스로만 작동합니다. 초대 URL의 토큰은 방의 접근 권한이므로 공유 대상에게만 전달해야 합니다. 브라우저 두 기기의 실제 통화 성공은 별도 수동 시험 증거가 필요합니다.
